Perfecto — con todo el contexto que diste armé (1) una pila tecnológica recomendada, (2) la estructura y modelos de datos clave, (3) endpoints y componentes UI, (4) integraciones (pagos, imágenes, monitoreo) y al final (5) el prompt definitivo que puedes pegar en un generador de código / equipo de devs o en una IA para que construya el proyecto. Lo hago pensando en una web responsive móvil-first, estética futurista y minimalista, y la carpeta local ~/Downloads/APP_YB_MOTOCOM como raíz del proyecto.

1) Stack recomendado (por qué)

Frontend: Next.js (App Router) + TypeScript — SEO, rutas, SSR/SSG/ISR cuando necesites, buen soporte para APIs, despliegue en Vercel.

Alternativa ligera: Vite + React si quieres SPA pura y build muy rápida.

UI / diseño: Tailwind CSS + shadcn/ui (mencionaste shadcn) para componentes modernos y consistentes. Usa inspiración de Mobbin para flujos UI y microinteracciones.

Backend / Auth / DB: Supabase (Postgres gestionado, Auth y Storage para imágenes). Fácil CRUD, realtime y respaldos.

Pagos: Stripe (global, Webhooks, tarjetas). Para mercado colombiano añade MercadoPago (o PayU) como opción local / wallets. (Para Daviplata/Nequi normalmente necesitas integraciones específicas o pasarelas locales — lo revisamos en la implementación).

Monitoreo & errores: Sentry (frontend + backend).

Observabilidad / auditoría: Normatron (mencionado) para documentación y auditorías IA; logs + auditoría en Postgres.

Tests: Vitest (unit) + Playwright (E2E).

CI/CD: GitHub Actions → desplegar en Vercel (Next.js) o Netlify.

Dev tooling: ESLint, Prettier, Husky (pre-commit), Commitlint.

Extras: Webhooks para sincronizar cierres / pagos; backups regulares de DB.

3) Modelo de datos esencial (Postgres / Supabase)

Tablas clave (columnas principales):

users: id, email, name, role (admin|seller|viewer), created_at

products: id, sku, title, description, price_cents, cost_cents, category, images[] (storage keys), stock_qty, active, created_at, updated_at

inventory_movements: id, product_id, qty, type (in|out|adjustment|sale), note, created_by, created_at

orders: id, user_id (customer), total_cents, currency, status (pending|paid|cancelled|refunded), payment_provider, created_at

order_items: id, order_id, product_id, qty, price_cents

payments: id, order_id, provider, provider_payment_id, amount_cents, method (card|transfer|wallet), status, created_at

daily_closures: id, date, cash_amount_cents, transfers_amount_cents, other_amount_cents, created_by, notes

audit_logs: id, actor_id, action, table_name, record_id, diff_json, created_at

Nota: imágenes en Supabase Storage y guarda la ruta en products.images.

4) Endpoints / funciones API (servidor / serverless)

Autenticados con JWT (Supabase Auth). Versiona API: /api/v1/...

POST /api/v1/auth/login (o usar Supabase Auth)

GET /api/v1/products — filtros (q, category, price range, active)

GET /api/v1/products/:id

POST /api/v1/products (admin) — subir imágenes -> Storage + guardar rutas

PUT /api/v1/products/:id (admin)

DELETE /api/v1/products/:id (admin)

POST /api/v1/orders — checkout (crea order + items + inicia payment)

POST /api/v1/payments/webhook — recibir webhooks Stripe/MercadoPago

GET /api/v1/reports/sales?from=&to=&group_by=day|week|month

POST /api/v1/inventory/adjust — registrar movimientos de inventario

POST /api/v1/daily_closures — registrar cierre diario (cash, transfers)

GET /api/v1/analytics/top-products?from=&to=&limit=10

GET /api/v1/admin/audit_logs (admin)

6) Pagos y wallet locales

Implementa Stripe para tarjetas y wallets soportadas por Stripe.

Para Nequi/Daviplata: normalmente requieren integración directa con pasarelas locales o con MercadoPago / PayU que ofrecen canales locales. Recomendación inicial: Stripe + MercadoPago y exponer como opciones en checkout; dejar “otros” que registren pago manual y conciliación en daily_closures.

Implementa webhooks para confirmar pagos y actualizar inventario / orders.

7) Monitoreo, auditoría y seguridad

Sentry en frontend + backend.

Registra todas las acciones críticas en audit_logs (quién, qué, antes/después).

Roles & permisos en Supabase (RLS) o en la capa API.

Validaciones server-side siempre para stock y cambios monetarios.

HTTPS obligatorio, CORS restringido.

Backups automáticos de Postgres.

8) Testing y despliegue

Unit tests con Vitest (components, utils).

E2E con Playwright (checkout flow, admin flows).

GitHub Actions: lint → tests → build → deploy (Vercel).

Env: usar Vault/Secrets en deploy (no env en repo).
